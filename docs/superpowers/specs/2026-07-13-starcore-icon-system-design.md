# 星核向导二次元图标系统设计

- 日期：2026-07-13
- 状态：首轮概念已完成；进入最终验收修复（final acceptance remediation）
- 适用项目：`chatai_deep` Flutter 客户端
- 首轮范围：概念验证，不替换现有运行时图标

## 1. 背景与目标

项目已经提供独立的二次元视觉模式，主色为紫色与玫红，界面采用浅色背景、较大圆角和轻发光。新的图标系统需要延续这套气质，同时建立一个可跨启动图标、导航、助手头像和工具入口复用的品牌角色。

本设计的目标是：

1. 建立无明确性别、年龄和人类外貌特征的数字精灵 IP「星核向导」。
2. 保持赛博酷飒，但不使用危险、攻击性或压迫感过强的造型。
3. 在 24px 导航/工具图标到 1024px 启动图标之间保持同一视觉身份。
4. 首轮用少量样稿验证系统是否成立，再决定是否批量扩展和接入运行时。

首轮不包含：

- 替换 Android、iOS、macOS、Windows 或 Web 的现有启动图标。
- 修改 Flutter 页面、导航组件或工具注册逻辑。
- 一次性制作完整助手头像库和全部工具图标。
- 引入新的 Flutter 图标依赖。

## 2. 已确认的视觉方向

### 2.1 核心角色

名称：星核向导（Starcore Guide）。

角色定位：可靠、冷静、敏捷的数字伙伴。它可以表达情绪，但不应被读作少女、少年、动物或传统机器人。

固定识别结构：

1. 圆形悬浮主体，承担亲和感和小尺寸稳定性。
2. 顶部四芒星核，作为最强品牌锚点。
3. 双侧几何光翼，形成横向轮廓并增加速度感。
4. 深色面罩与发光眼神，用最少线条表达性格。
5. 无头发、服装、人体比例和性别化五官。

视觉比例为约 70% 圆润体块、30% 锐利切角。整体可以酷飒，但不得出现武器、尖牙、骷髅、血迹或具有敌意的红眼。

### 2.2 颜色系统

颜色与现有 `AppThemeFactory.anime()` 保持亲缘关系，并增加适合图标插画的明暗层级：

| Token | 色值 | 用途 |
| --- | --- | --- |
| Midnight | `#120D24` | 启动图标深色底、面罩和高对比结构 |
| Brand Purple | `#6D28D9` | 与现有二次元主题 primary 对齐 |
| Core Violet | `#7C3AED` | 星灵主体中间色和选中态填充 |
| Energy Magenta | `#BE185D` | 与现有 secondary 对齐，用于主要能量强调 |
| Energy Highlight | `#EC4899` | 大尺寸插画中的高光，不用于大面积填充 |
| Digital Cyan | `#22D3EE` | 数字边缘、面罩描边和交互状态高光 |
| Highlight | `#F5F3FF` | 眼神、星核和关键轮廓的高光 |

单个 24px 图标最多同时使用三种颜色。未选中态以单色或双色线框为主，避免在小尺寸堆叠全部品牌色。

### 2.3 线条与光效

- 24px 图标的等效主描边不低于 1.75px。
- 线端和连接处以圆角为主，局部使用切角表达赛博感。
- 发光只能强化星核、眼神或选中态，不能让外轮廓变糊。
- 24px 图标不绘制电路纹理、颗粒或细碎星点。
- 大尺寸插画采用清晰赛璐璐块面，不使用写实毛发、玻璃或复杂半透明材质。

## 3. 首轮概念资产

首轮统一输出到 `docs/design-assets/starcore-guide/`。这些文件只用于评审，不在 `pubspec.yaml` 注册，也不被运行时代码引用。

### 3.1 App 启动图标

文件：`app-icon-concept.png`

- 数量：1
- 尺寸：1024×1024
- 背景：不透明午夜紫到品牌紫/玫红的克制渐变
- 构图：星核、面罩和双光翼位于中心安全区，主体占画布约 72%
- 禁止：文字、边框文字、平台徽标、水印、透明角和过细装饰

该文件只是母版概念，不直接覆盖各平台现有 AppIcon 资源。

### 3.2 导航图标样例

文件：

- `nav-chat-default.svg`
- `nav-chat-selected.svg`
- `nav-create-default.svg`
- `nav-create-selected.svg`

规则：

- 数量：2 个语义、各 2 个状态
- 画板：24×24 viewBox
- 默认态：功能轮廓优先，使用紫色线框
- 选中态：保留原语义轮廓，增加星核锚点、深色填充和冰蓝/玫红高光
- 聊天图标继续使用对话气泡语义；创作图标继续使用笔尖/创作语义
- 星核只做识别锚点，不能遮挡主要功能符号

### 3.3 助手头像样例

文件：

- `assistant-explorer.png`
- `assistant-creator.png`

规则：

- 数量：2
- 尺寸：512×512
- 构图：针对圆形裁切，星核和面罩必须位于中央 70% 安全区
- 探索向导：冰蓝能量强调，眼神更专注
- 创作搭档：玫红能量强调，可增加短光带或创作脉冲配件
- 两个头像必须复用同一主体骨架，只通过颜色、眼神和配件区分
- 两个头像的前景宽度占画布比例允许最多相差 5 个百分点；当前实测差值为 4.883 个百分点。该容差只处理呈现尺度，不允许身份骨架漂移，也不降低中央 70% 圆形裁切安全要求
- 头像使用完整背景圆，不要求透明通道

### 3.4 工具图标样例

文件：

- `tool-web-search.svg`
- `tool-knowledge-search.svg`

规则：

- 数量：2
- 画板：24×24 viewBox
- 联网搜索以放大镜为第一语义，星核放在镜片内或连接点
- 知识检索以打开的书或知识页为第一语义，星核放在中缝或检索焦点
- 工具语义优先级高于 IP 装饰，首次看到时应无需文字也能区分

### 3.5 总览稿

文件：`contact-sheet.png`

总览稿固定为 2048×1536、不透明，并保留 A–D 四组资产概览。六个导航/工具 SVG 必须分别在 `#FFFBFE`、`#FCE7F3`、`#120D24` 三种背景上，以 DPR 1 的真实 CSS 像素同时展示 24px、32px、48px，形成 6×3×3 的明确验收矩阵。

矢量的原始验收尺寸就是矩阵中的真实 24×24 样本。栅格原件仍是 canonical 的 1024×1024 App icon 与两张 512×512 头像：总览 PNG 可显示带原生尺寸标签的缩略图，`contact-sheet.html` 必须用这些缩略图直接链接原始 PNG，供单独 1:1 检查，不在 2048×1536 总览中伪装成原尺寸。

## 4. 交付方式

采用混合资产方式：

- 启动图标和助手头像使用高质量赛璐璐栅格插画，以保留角色表现力。
- 导航和工具图标使用确定性的 SVG 母版，以保证小尺寸清晰、状态一致和后续可维护性。
- SVG 在首轮仅作为设计母版；正式接入时再决定转换为 Flutter 矢量路径、PNG 多倍率资源，或引入现有可接受的 SVG 渲染方式。

选择混合方式的原因是：全栅格方案难以保证 24px 图标一致性，全矢量方案又会削弱启动图标和头像的二次元角色质感。

### 4.1 本地渲染边界

`render_contact_sheet.cjs` 是本轮固定评审机上的确定性本地 renderer，不承诺跨机器或 CI 的 PNG 字节级 hash 一致。脚本依次从 `STARCORE_PLAYWRIGHT_MODULE`、本地 `playwright` 包和已知 bundled fallback 解析 Playwright，并在截图前等待字体与所有图片完成解码，同时拒绝破图和 2048×1536 之外的滚动溢出。

在受支持的固定机器上，连续两次渲染必须得到相同 SHA-256。仓库中提交的 `contact-sheet.png` 是 canonical 评审制品；其他环境若因浏览器 revision 或系统字体不同而产生差异，应以该 PNG 与 HTML 源进行人工比对，而不是宣称跨机 hash 必须一致。

## 5. 生成与迭代流程

1. 先生成启动图标母版，确定星核向导的唯一标准轮廓。
2. 从母版提取角色约束，再生成两个助手头像，禁止主体骨架漂移。
3. 根据标准轮廓手工构建导航和工具 SVG，不让生成模型决定小尺寸路径。
4. 输出总览稿，在 `#FFFBFE`、`#FCE7F3` 和 `#120D24` 三种真实背景上检查全部六个功能 SVG 的 24/32/48px 样本，并从 HTML 直链单独检查三张栅格原件。
5. 每轮只修改一个变量，例如眼神、星核大小或光翼角度，避免同时改变角色身份。

如果栅格生成结果出现性别化、人形化、轮廓漂移、文字或水印，直接判为不合格并重新生成。SVG 若在 24px 出现粘连、断线或语义不清，优先删减装饰，而不是继续缩细描边。

## 6. 验收标准

### 6.1 品牌一致性

- 大角色资产（App icon 与两个助手头像）必须露出四芒星核、面罩、双光翼中的至少两个核心特征。
- 24px 功能资产以功能语义优先：每个工具图标必须带一个四芒星锚点；每组导航默认/选中状态对作为品牌单元，默认态可以省略星核，但选中态必须露出四芒星锚点。六个功能 SVG 不追加第二个面罩或光翼提示。
- 角色保持非人类、无性别表达。
- 颜色与现有二次元主题协调，不引入新的主品牌色。

### 6.2 小尺寸可用性

- 全部六个导航/工具 SVG 在 24px、32px、48px、DPR 1 下均能区分语义；其中 24px 是矢量原始验收尺寸。
- 默认态和选中态除颜色外还必须有填充、星核或轮廓变化，不能只依赖颜色。
- 6×3×3 验收矩阵必须逐一覆盖 `#FFFBFE`、`#FCE7F3` 和 `#120D24`，标签需明确背景色与真实尺寸，且无明显轮廓丢失。

### 6.3 构图与裁切

- 启动图标在圆角蒙版下不裁掉星核和光翼。
- 助手头像采用圆形裁切时，面罩、眼神和星核仍完整可见。
- 所有资产不含文字、水印或第三方商标元素。

### 6.4 首轮完成定义

以下文件全部存在并通过人工视觉检查，即视为首轮完成：

1. 1 个启动图标概念 PNG。
2. 4 个导航状态 SVG。
3. 2 个助手头像 PNG。
4. 2 个工具图标 SVG。
5. 1 个总览 PNG。

机器验收还必须满足：validator 的 12 项回归测试全绿、完整资产合同通过、六个 SVG XML 合法、固定评审机双次渲染 hash 一致、总览为 2048×1536 不透明且无破图/裁切/溢出，并已从 HTML 直链对三张栅格原件做 1:1 检查。

首轮完成不代表已接入 App。批量扩展与平台替换需要在首轮视觉确认后另行规划。
