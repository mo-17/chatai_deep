# ChatAI Deep 翻译适配加固设计

- 日期：2026-07-19
- 状态：书面规格已确认，等待实施
- 依赖设计：`2026-07-16-streaming-translation-reliability-design.md`
- 适用范围：酒馆房间、角色卡、酒馆模板中文副本，以及这些入口复用的翻译模型选择与任务进度界面
- 核心目标：在不产生隐式模型请求的前提下，提前暴露不可用配置，并让超长字段的进度真实反映已完成正文量

## 1. 背景与当前状态

上一阶段已经完成流式传输、活动超时、长字段小块串行翻译、块级检查点、真取消、失败分类和任务级模型选择。当前基线测试为 `1431/1431`，这些能力与兼容性约束必须保留。

实际使用仍有三个适配缺口：

1. 模型选择器只能判断“已启用、已填写 API Key、已填写模型 ID”，不能证明该组合真的支持当前翻译请求、SSE 流、JSON 输出或关闭 Thinking 的参数。
2. 任务进度主要按字段数量分配。一个 13 字名称和一个 33,322 字世界书各占一个字段权重，因此世界书连续完成多个块时，总进度仍可能长时间停在同一百分比。
3. 某些组合在发起请求前就可以判断为不可执行，例如游客选择后端代理、移动端使用 `localhost`、Android 商店构建直连明文 HTTP 端点。当前提示与拦截不统一。

本设计只补齐以上适配层，不更改已验证的请求重试、分块边界、检查点格式或翻译任务恢复原则。

## 2. 决策摘要

采用“纯本地资格检查 + 用户显式模型预检 + 正文字符计权进度”的兼容优先方案：

1. 模型预检永不自动运行。只有用户点击“测试翻译模型”并确认会发送一次小型请求后，才允许消耗 Token。
2. 预检复用正式翻译的流式执行器和 Thinking 参数适配器，用无用户数据的固定小提示验证真实链路，而不是另造一条与生产路径不同的 ping。
3. 预检结果按账号和配置指纹缓存七天；模型、模式、端点或推理策略发生变化时立即视为未验证。
4. 未验证或因瞬时网络问题验证失败的模型仍可在明确警告后使用；确定性配置错误必须在创建任务前阻止。
5. 游客模式下的后端代理、Android 商店构建中的不允许明文 HTTP 等情况属于硬拦截；移动端 loopback 地址属于强警告，并给出局域网地址指引。
6. 任务进度改为按实际送入模型的可见自然语言正文字符数计权；Base64、JSON 包装、不可变字段和保护标记不计入。
7. 每个分块成功或被用户明确“保留原文”后，其源正文字符数立即计入已解决工作量，保证超长世界书的总进度持续前进且不倒退。
8. 旧任务、旧检查点和无法解析的异常输入继续使用现有字段进度算法，不进行数据库迁移。

## 3. 目标与非目标

### 3.1 目标

- 在任务创建前发现确定性的账号、执行模式、端点和传输兼容问题。
- 用户能主动验证一个模型是否适合翻译，并看到验证时间、首事件延迟和可操作错误。
- 不因打开选择器、切换模型、恢复任务或进入页面而偷偷发请求。
- 33,322 字世界书每完成若干分块都能推动整体进度，不再长时间固定在 60% 一类的字段边界。
- 预估字符、任务进度和详情日志使用同一正文口径。
- 保持已有流式取消、退避、检查点、失败保留与后台恢复行为不变。
- 不在缓存、任务表或日志中保存 API Key、原始自定义端点或预检响应正文。

### 3.2 非目标

- 本期不根据预检延迟自动选择“最快模型”。
- 本期不实现自适应首事件、空闲或总超时；仅记录安全的延迟指标，为后续设计提供数据。
- 本期不增加系统通知，也不补 OHOS 后台调度器。
- 本期不自动遍历、测试所有已配置模型。
- 本期不为未知 OpenAI 兼容端点猜测 Thinking 参数。
- 本期不修改长字段切块尺寸、串行策略、重试次数或检查点持久化结构。

## 4. 总体结构

新增三个职责清晰、可独立测试的组件：

```text
翻译设置/模型选择器
  ├─ TranslationModelEligibilityEvaluator 纯本地、零请求
  ├─ TranslationModelProbeService          仅用户显式触发
  │    └─ TranslationStreamExecutor         复用正式流式链路
  └─ TranslationModelProbeCache            账号隔离的本地短期缓存

创建/恢复翻译任务
  ├─ EligibilityEvaluator 再校验，防止绕过 UI
  ├─ TranslationWorkEstimator 计算正文总量
  └─ 现有 runner / chunk planner / checkpoint
       └─ 每块完成后更新 completedRunes / totalRunes
```

资格检查与预检必须分开：前者只基于本地事实并作为安全边界；后者访问第三方服务，只提供兼容性证据，不能代替任务开始前的本地再校验。

## 5. 模型可执行性检查

### 5.1 输入与输出

`TranslationModelEligibilityEvaluator` 接收以下只读信息：

- 当前账号是否为游客；
- 执行模式：本地直连或后端代理；
- 服务商是否存在、是否启用；
- 模型 ID、API Key、有效端点；
- 当前平台和发行渠道能力，例如 Android 商店构建是否禁止明文流量。

输出统一为：

```dart
enum TranslationEligibilityLevel { allowed, warning, blocked }

class TranslationEligibilityResult {
  final TranslationEligibilityLevel level;
  final String code;
  final String message;
  final String? actionLabel;
}
```

`code` 是稳定、无敏感信息的机器码；界面文案不参与业务判断。

### 5.2 判定矩阵

| 条件 | 结果 | 处理 |
| --- | --- | --- |
| 服务商已删除、已停用、缺少模型 ID 或直连缺少 API Key | blocked | 跳转 AI 服务设置，沿用 `needsConfiguration` 恢复路径 |
| 游客选择后端代理 | blocked | 说明后端需要登录，提供登录或改选本地直连 |
| Android 商店构建使用平台不允许的明文 HTTP 直连端点 | blocked | 要求改用 HTTPS 或后端代理 |
| Android/iOS 选择 `localhost`、`127.0.0.1` 或 `[::1]` | warning | 说明该地址通常指向手机/模拟器本身，建议填写电脑局域网 IP；不引入设备识别依赖，不武断判断真机 |
| 已配置但从未预检 | warning | 允许继续，开始前明确“尚未验证” |
| 预检因超时、限流或临时网络失败 | warning | 允许重试预检或继续任务，不形成永久封禁 |
| 最近预检为鉴权、API 不兼容或输出无效 | warning | 展示具体修复建议；若本地配置本身已构成硬错误，仍按前述 blocked 处理 |
| 七天内同一配置指纹预检成功 | allowed | 显示“已验证”及安全延迟摘要 |

资格检查必须在两个位置执行：

1. 模型选择器中即时展示状态；
2. 创建任务、恢复任务或换模型继续之前再次执行。

第二层检查避免未来新增入口绕过 UI，也覆盖用户停留在弹窗期间配置被删除或账号状态变化的情况。

## 6. 显式模型预检

### 6.1 用户触发与 Token 边界

选择器提供“测试翻译模型”动作。首次点击展示说明：

> 将向所选模型发送一次不含你的角色卡内容的小型流式翻译请求，可能产生少量 Token 费用。

只有用户确认后才调用预检服务。以下行为一律不得触发请求：

- 打开模型选择器；
- 切换选中模型；
- 查看历史预检结果；
- 创建页面、App 启动或后台恢复；
- 缓存过期；
- 资格检查。

同一配置指纹同时只允许一个预检请求。关闭弹窗或点击取消时，必须沿用正式翻译的取消通道关闭底层连接；预检不创建持久翻译任务。

### 6.2 测试请求

预检使用固定、无用户数据的小型输入，例如要求把一个短英文词组翻译成简体中文并返回单字段 JSON。请求需要：

- 通过当前所选执行模式和服务商；
- 使用正式 `TranslationStreamExecutor`；
- 使用正式 `ReasoningControlAdapter` 的“关闭 Thinking”决策；
- 走正式 SSE 解析和正文累计；
- 使用独立的小输出上限，避免不必要费用；
- 验证流中至少收到一个有效事件，并能解析为预期结构；
- 不把响应正文、推理正文或服务商原始错误体写入缓存与常规日志。

预检只证明“在测试时此配置完成了同类小请求”，不承诺超长翻译一定成功。

### 6.3 错误分类

预检对外只返回安全错误码和可操作提示：

| 安全错误码 | 含义 | 建议 |
| --- | --- | --- |
| `auth_failed` | API Key、权限或后端登录无效 | 检查密钥、账号或代理授权 |
| `unsupported_api` | 端点不兼容 SSE、JSON 或请求参数 | 检查 Base URL、模型和 OpenAI 兼容性 |
| `rate_limited` | 429 或等价限流 | 稍后重试或换模型 |
| `first_event_timeout` | 首事件超时 | 检查网络或换快速模型 |
| `idle_timeout` | 流已开始但长时间无活动 | 重试或换模型 |
| `network_unreachable` | DNS、连接、TLS 等网络错误 | 检查网络与端点 |
| `invalid_output` | 返回成功但正文不符合测试结构 | 换模型或关闭自定义响应包装 |
| `cancelled` | 用户主动取消 | 不记为失败 |
| `unknown` | 其余已脱敏错误 | 允许重试并保留诊断日志编号 |

服务商原始错误可以用于当前界面的临时诊断，但展示前必须去除认证头、API Key、查询参数和超长响应体；持久缓存只存安全错误码。

## 7. 预检缓存与失效

### 7.1 账号隔离

缓存使用账号级 HiCache key：

```text
translation_model_probe_v1_<accountHash>
```

游客使用现有独立账号哈希。缓存只对当前设备有效，不进入备份、不跨账号同步；注销与账号切换后不会读取另一账号结果。

### 7.2 配置指纹

缓存索引使用本地计算的单向摘要，不保存原始敏感配置。指纹输入至少包含：

- 执行模式；
- provider ID 与 provider code；
- model ID；
- 规范化后的有效 endpoint；
- 当前 Thinking 控制策略版本；
- 预检协议版本。

指纹仅保存哈希值。API Key 不进入指纹，避免任何形式的密钥派生值落盘；当 API Key 被编辑时，由设置保存流程显式清除该 provider 的预检记录。这样既避免持久化密钥特征，又能正确失效。

### 7.3 缓存结构

单条记录只包含：

```dart
class TranslationModelProbeRecord {
  final String fingerprint;
  final String status; // verified / failed
  final DateTime checkedAt;
  final int? firstEventMs;
  final int? totalMs;
  final String? safeErrorCode;
  final bool reasoningControlSuppressed;
}
```

- 成功与失败记录统一在七天后过期；
- 配置指纹变化后旧记录不可命中；
- 取消不写入失败缓存；
- 延迟按整数毫秒保存，不保存响应内容或 Token 详情；
- 可限制每账号最多保留最近 50 条，写入时清理更旧记录。

`reasoningControlSuppressed=true` 表示所选模型不适用已知 Thinking 关闭参数，因此正式请求也没有发送猜测参数；它不是错误。

## 8. 模型选择器交互

每个模型行显示以下一种辅助状态：

- `已验证 · 首响应 1.2 秒`；
- `未验证`；
- `验证失败 · 鉴权失败`；
- `配置不可用`；
- `地址可能无法从手机访问`。

底部操作区包含：

- “测试翻译模型”：显式预检；
- “开始翻译”或“换此模型继续”：创建/恢复任务；
- 硬拦截时的“去配置”“去登录”等修复动作。

未验证或瞬时失败时，用户点击开始会看到一次简短确认，不要求必须预检成功。硬拦截时开始按钮不可提交，并显示唯一、明确的修复路径。

已有 `needsConfiguration` 任务恢复逻辑继续作为服务商被删除、密钥丢失或模型为空后的入口；本设计不另建平行恢复状态。

## 9. 正文字符工作量估算

### 9.1 单一口径

新增 `TranslationWorkEstimator`，由任务创建、进度上报和预计字符展示共同使用。计数单位为 Dart Unicode rune 数，而不是 UTF-16 code unit、UTF-8 字节数或序列化 JSON 长度。

只计入实际要送入模型、需要翻译的可见自然语言正文：

- 名称、简介、人设、开场、示例对话、世界书正文等可翻译字段；
- 酒馆原始 envelope 经过现有 translation view 提取后的字段正文；
- 可选额外开场中实际需要翻译的正文。

明确排除：

- PNG/Base64、压缩数据和二进制载荷；
- JSON 键名、引号、逗号和结构包装；
- ID、版本、时间戳、布尔值等不可变元数据；
- 为占位保护加入的 marker 文本；
- 不会发送给模型的空字段或跳过字段。

估算器必须复用现有原始 envelope 的 translation view/字段选择逻辑，不能再维护一份容易漂移的“猜测字段列表”。

### 9.2 任务进度映射

任务保存源输入后即可重算总工作量，不要求新增数据库列。对新任务，标准映射为：

```text
bodyRatio = resolvedSourceRunes / totalSourceRunes
translationProgress = 4% + bodyRatio × 90%
保存阶段 = 96%
完成阶段 = 100%
```

规则如下：

1. 翻译阶段显示范围为 4% 到 94%；保存成功后进入 96%，终态为 100%。
2. `resolvedSourceRunes` 只在字段或分块形成可恢复检查点后增加。
3. 一个分块成功后，增加该分块对应的源 rune 数，而不是模型输出长度。
4. 用户明确选择“保留失败块原文并完成”后，该块也视为已解决并增加源 rune 数，同时保留现有警告状态。
5. 自动细分或重试不增加完成量，避免重复计数。
6. runner 每次启动时记录 `anchorProgress` 与 `anchorResolvedRunes`。若旧任务的已持久化进度高于标准 rune 映射，后续剩余字符按 `anchorProgress..94%` 重新线性映射；这样兼顾不倒退与“每个新检查点都可见前进”。
7. 每次保存检查点时同时保存计算后的现有 `progress`；重启后用新的锚点继续，不需要增加数据库字段。
8. 计算结果必须不低于任务当前已持久化进度，保证重算、恢复和块重规划时不倒退。
9. 总字符为零、旧源格式无法解析或估算器异常时，回退到现有字段进度公式。

旧任务锚点映射的精确定义为：

```text
remainingRatio =
  (resolvedSourceRunes - anchorResolvedRunes) /
  (totalSourceRunes - anchorResolvedRunes)

anchoredProgress =
  anchorProgress + remainingRatio × (94% - anchorProgress)
```

分母为零时直接进入 94%。最终值取标准映射、锚点映射和已持久化进度的最大值，再限制在翻译阶段范围内。

不按模型输出 rune 数计权，因为译文长度会因语言和模型而变化，无法稳定代表已处理的源工作量。

### 9.3 进度事件与详情

在保持旧调用方兼容的前提下，为进度事件增加可空字段：

```dart
final int? completedRunes;
final int? totalRunes;
```

旧任务或回退路径可继续传 `null`。UI 仅在两个值都有效时显示字符详情，例如：

```text
世界书 · 块 3/16 · 已完成 8,420/33,322 字
```

分块正在流式输出时不伪造精确的块内百分比；详情继续显示“等待首个响应”“接收中”等阶段。块形成检查点时字符数和总进度一起跃升，做到真实、单调且可解释。

任务创建确认框中的“预计翻译字符数”也改用同一个估算器，避免把 Base64 或 JSON 包装算进成本提示。

## 10. 任务恢复与兼容性

- 不修改现有任务表、块级检查点或源 payload 结构。
- 新 runner 可从不可变源 payload 与现有检查点重算 `totalRunes` 和 `resolvedSourceRunes`。
- 已存在任务没有字符统计元数据时，优先尝试重算；无法重算则使用旧字段进度。
- 已持久化的 `progress` 是单调下限，新算法不得让恢复后的 UI 百分比下降。
- 旧版客户端可以忽略新增的可空进度字段；新版客户端也能读取旧任务。
- 换模型继续只改变后续请求配置，不清除已完成字符或块检查点。
- 预检缓存与任务恢复完全解耦：缓存过期不会暂停任务，恢复任务也不会自动发预检请求。

## 11. 安全、隐私与费用约束

1. 预检只能由用户动作触发，并在首次发送前明确说明少量 Token 费用。
2. 预检提示词使用固定测试文本，禁止带入角色卡、房间、世界书、账号资料或剪贴板内容。
3. API Key 不写入任务、指纹、预检记录、日志或错误文案。
4. 原始自定义 endpoint 不持久化到预检缓存；只保存配置指纹。
5. 后端代理在游客模式下必须于客户端创建请求前阻止，不能依赖后端 401 才反馈。
6. Android 商店构建的明文限制由资格检查与平台网络策略共同防守，不能通过隐藏警告绕过。
7. 预检失败不会自动切换模型、修改全局聊天设置或反复重试扣费。
8. 延迟数据仅用于本地展示和未来超时设计，不上传分析服务。

## 12. 测试策略

### 12.1 单元测试

`TranslationModelEligibilityEvaluator`：

- 游客 + 后端代理为 blocked；
- 游客 + 配置完整的本地直连可用；
- provider 缺失、停用、空模型、直连空 key 为 blocked；
- mobile loopback 为 warning；
- Android 商店构建不允许的 HTTP 为 blocked；
- 瞬时预检失败不会变成资格硬拦截。

`TranslationModelProbeCache`：

- 账号隔离；
- 七天 TTL；
- 配置/策略/协议变化导致指纹失效；
- API Key 修改通过显式失效清除记录；
- 取消不落失败缓存；
- 最多 50 条与脱敏序列化。

`TranslationWorkEstimator`：

- 中文、emoji、组合字符按 rune 计数；
- JSON 包装与 Base64 不计入；
- 原始 Tavern envelope 只计 translation view 正文；
- 空字段、跳过字段和保护 marker 不计入；
- 额外开场纳入总量；
- 检查点重算 resolved runes；
- 保留原文计入已解决量但保留警告；
- 失败、重试、细分不重复计数；
- 异常旧 payload 回退现有公式；
- 进度单调不倒退。

### 12.2 传输与服务测试

- 标准正文流预检成功；

- 鉴权、429、首事件超时、空闲超时、非法 JSON；
- 用户取消后底层连接关闭；
- 同一指纹并发点击只产生一个请求；
- 打开/切换/恢复页面产生零请求。

## 13. 验收标准

以用户曾遇到的 33,322 字世界书作为主要验收样本：

1. 打开翻译设置、切换多个模型并关闭页面，网络记录中没有预检请求。
2. 点击“测试翻译模型”后，界面先说明会产生小额 Token；确认后只发送一次固定小请求。
3. 成功预检显示验证时间和首事件延迟；修改模型或端点后状态回到未验证。
4. 游客选择后端代理时，在发请求前被拦截并得到登录/本地直连指引。
5. 移动端 loopback 地址得到明确警告；Android 商店构建中的不允许明文 HTTP 被硬拦截。
6. 任务预估不包含 PNG/Base64 和 JSON 包装，只反映可翻译正文。
7. 世界书每个成功块形成检查点后，`completedRunes` 增长，整体百分比单调前进；不会因字段权重而长时间固定。
8. 暂停、重启、恢复和换模型继续后，字符完成量不丢失、不重复、不倒退。
9. 保留失败块原文后任务可以到达 100%，同时维持部分原文警告。
10. 旧任务和无法重算的异常输入仍可用旧进度算法完成，不要求数据库迁移。
11. 全量基线测试与新增测试通过，且没有改变现有分块、超时、重试和检查点行为。

## 14. 实施边界与顺序

后续实施计划应拆成可独立回滚的提交，建议顺序为：

1. 先为资格检查和正文估算器补失败测试，再实现纯逻辑组件。
2. 扩展可空进度事件并接入 runner/checkpoint 重算，完成进度与兼容性测试。
3. 实现账号级预检缓存、配置失效和脱敏测试。
4. 基于现有流式执行器实现显式预检服务与本地假 SSE 测试。
5. 接入模型选择器状态、确认、修复动作和 Widget 测试。
6. 运行目标测试、全量 core 测试和 analyze；最后做一次 iOS 模拟器手动验收。

每一步都不得提前改变长字段切块阈值或超时策略。若实现时发现必须修改既有持久格式、需要新增平台依赖，或无法在不自动请求的前提下提供状态，应先回到设计评审，不直接扩大范围。
