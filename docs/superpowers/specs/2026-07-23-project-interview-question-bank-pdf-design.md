# 艾普项目高级岗位面试题库 PDF 重设计规范

状态：已批准  
批准日期：2026-07-23  
源文档：`docs/project-interview-question-bank.md`  
目标文件：`output/pdf/aipu-senior-role-interview-question-bank.pdf`

## 1. 目标与范围

将项目面试题库转换为一份符合大型科技企业内部评审标准的 A4 面试官手册。成品同时服务于屏幕查阅、面试现场操作和纸面批注，必须完整保留题目、盲面材料、项目情景、参考答案、追问、风险信号、评分锚点、参考入口、综合评估和维护规则。

本次重设计只改变 PDF 的信息架构、视觉语言、分页行为和验证合同，不修改源 Markdown 的项目事实、题目答案或评分口径。源文档仍是唯一内容来源。

## 2. 已批准的设计决策

### 2.1 视觉方向

采用 B 类视觉人格“工程蓝图 Blueprint”，但不把整本 PDF 做成深色文档：

- 封面和题组章节页使用深色工程蓝图。
- 题目、目录、说明、表格和记录表使用白底正文页。
- 深色页面负责品牌识别和章节导航，白底页面负责长时间阅读与低成本打印。
- 蓝图网格只作为低对比背景，不得穿过正文或降低可读性。

### 2.2 题目页架构

采用 A“全宽规范流”：

- 题目标题、问题、考察点、答案要点和评分内容沿单一主阅读轴自上而下排列。
- 主要内容不使用固定侧栏，避免窄栏压缩中文和代码路径。
- 只有“追问 + 风险信号”这类短块在两块都能完整容纳时可以并排；任一块过长时自动退回上下堆叠。
- 题目标签条与正文面板使用同一父容器中的独立行；两行可以共享一条边界线，但背景、边框和内边距的相交面积必须为 0。

### 2.3 分页策略

- 每道题优先从新页开始。
- 一页能够完整容纳时保持一题一页。
- 长题自然续页，不缩小到不可读字号，也不裁切内容。
- 续页重复章节和题号上下文，但不重复完整题干。
- 标签必须和对应正文的起始内容同页；大段答案可在段内继续分页。

### 5.1 色彩令牌

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| Dark Navy | `#0D263E` | 封面和章节页底色 |
| Body Navy | `#163A5F` | 白底页标题、标签与结构线 |
| Engineering Blue | `#2F6FED` | 题号、重点边线与蓝图强调 |
| Blueprint Sky | `#62ADFF` | 深色页大编号和技术标记 |
| Ink | `#172B3A` | 正文 |
| Muted | `#536575` | 次级信息、页眉页脚 |
| Paper | `#FFFFFF` | 正文页面 |
| Soft Surface | `#F6F8FA` | 普通信息面板 |
| Line | `#D6DEE6` | 分隔线和边框 |
| Risk | `#B42318` / `#FEF3F2` | 风险文字、边线和浅红背景 |
| Score | `#1D4ED8` / `#EFF6FF` | 评分文字、边线和浅蓝背景 |
| Info | `#2F6FED` / `#EEF4FF` | 题前材料与问题提示 |

颜色不是唯一的语义信号。风险、评分和信息块同时依靠中文标签、英文技术标记、边线和位置区分，确保灰度打印仍可理解。

### 5.2 字体角色

- 中文标题：STHeiti Medium，优先使用可嵌入子字体索引 1。
- 中文正文：STHeiti Light，优先使用可嵌入子字体索引 1。
- 技术标签、题号和代码：Menlo Regular；缺失时仅 ASCII 内容可退回 Courier。
- 若没有可嵌入且覆盖中文的正文或标题字体，生成过程必须失败，不得静默使用会产生方框或缺字的字体。

基准字号：

| 角色 | 字号 / 行高 |
| --- | --- |
| 封面标题 | 29 pt / 39 pt |
| 章节大编号 | 64-72 pt |
| 章节标题 | 24 pt / 34 pt |
| 题目标题 | 15 pt / 20 pt |
| 问题正文 | 10.2 pt / 16 pt |
| 普通正文 | 9.2 pt / 15 pt |
| 字段标签 | 8.2-9.4 pt / 12-13 pt |
| 表格正文 | 不低于 7.8 pt / 11 pt |
| 页眉页脚 | 不低于 7.1 pt |

不得通过全局缩小字号解决分页问题。

### 5.3 间距与线条

- 使用 4 pt 基础步长，常用间距为 4、8、12、16、24 和 32 pt。
- 正文面板边线控制在 0.45-0.8 pt。
- 白底页不使用大面积阴影；层级主要依靠留白、线条、背景明度和字号。
- 深色页网格透明度控制在 8%-12%，不得覆盖文字。
- 圆角仅用于少量题号或状态胶囊；大部分内容框保持轻微或无圆角的工程规范感。

## 6. 页面模板

### 6.1 封面

封面使用 Dark Navy 全页底色、左侧 Engineering Blue 竖向识别条和低对比蓝图网格。内容包含中文标题、中文副标题、英文标识、版本、日期、密级和内容规模。

封面不显示普通页眉页脚，不使用项目截图、插画或外部品牌 Logo。

### 6.2 文档控制与普通正文页

普通正文页使用白底：

- 页眉左侧显示当前章节。
- 页眉右侧显示当前题号；非题目页显示文档简称。
- 页脚左侧显示“面试官版 / 内部使用”。
- 页脚中部显示内容快照日期。
- 页脚右侧显示“第 X / Y 页”。

页眉和页脚家具绘制在正文 Frame 外，不占用正文流式布局空间，也不得与正文背景框相交。

文档控制页的标签与值面板必须分离。标签之后至少保留 3 pt 可测净距；值面板底边与下一标签顶边也至少保留 3 pt。

### 6.3 目录、路线和表格页

- 目录使用可点击条目和点引导线。
- 抽题路线保留题号分组，不把整串题号压缩成不可读文本。
- 表格允许跨页并重复表头。
- 超宽能力表拆分为语义连续的关联表，不横向缩放整页。
- 表格文本保持可抽取，不能栅格化为图片。

### 6.4 题组章节页

章节页使用 Dark Navy 全页底色，包含：

- 两位章节编号。
- 中文题组名称和英文技术标记。
- 能力关键词。
- 题号范围或题量。
- 统一评分范围。

章节页装饰线位于内容层下方，并与所有指标框保持至少 8 pt 安全距离。章节页不承载长正文。

### 6.5 题目首页

题目页按以下顺序输出：

1. 章节与题号上下文
2. 题号、题目标题和能力标签
3. 题前材料（盲面提供，存在时）
4. 问题
5. 项目情景（存在时）
6. 考察点
7. 答案要点
8. 追问
9. 风险信号
10. 评分锚点
11. 参考入口（存在时）
12. 面试官记录区

`<details>` 和 `<summary>` 只属于 Markdown 源格式，PDF 中必须全部展开为静态可见内容。

主内容采用全宽单列。仅当追问和风险信号都能在各自栏中完整显示且字号不变时，允许使用等高双列；否则使用上下堆叠。

### 6.6 长题续页

长题续页遵循三条硬规则：

- `CONTINUED`：续页页眉显示“题号 · CONTINUED”，并保留章节名。
- `KEEP BLOCK`：字段标签和正文起始至少两行作为一个不可拆的起始单元，不允许页底孤立标签。
- `SAFE FOOTER`：所有正文和面板必须停在正文 Frame 内，页脚安全区内不得出现正文像素。

续页不重复完整题目标题和问题。若单个答案段落超过一页，段落本身可以继续拆分，但不得丢字、重复文字或跳过后续字段。

### 6.7 综合评估与记录表

原 Markdown 代码块形式的记录模板转换为可打印表单，保留候选人、岗位、时长、题号、强证据、主要风险、专项判断、题目平均分、换算分、建议和下一轮重点。

记录表只提供纸面书写区域，不新增交互式 AcroForm 字段，也不改变源题库的评价标准。

## 7. 分页与防遮挡合同

### 7.1 页面边界

- 正文只允许出现在 A4 Body Frame 内。
- 页眉底线、页脚顶线和所有页码均在 Frame 外绘制。
- Flowable 的实际绘制边界必须包含背景、边框和 `borderPadding`；不能只依据文字的 `wrap()` 高度判断间距。
- 任何绝对定位装饰都必须位于内容层下方，并通过几何测试证明没有侵入正文。

### 7.2 字段边界

- 题目页使用“集成标签行”模式：标签行和正文行是同一父容器中的两个独立单元格，可以共边，但垂直相交高度必须为 0。
- 集成标签行的正文背景从标签行底边开始，既不能向上覆盖标签文字，也不能留下不可控的负间距。
- 文档控制等页面使用“外置标签”模式：标签底边到值面板背景顶边的净距不得小于 3 pt，值面板背景底边到下一标签顶边也不得小于 3 pt。
- 两种模式都不得使用会越过自身测量高度、向相邻文字扩张的背景框。
- 风险、评分、题前材料和普通字段使用同一边界算法，不允许只修复某一类面板。
- 面板内文字必须完整落在内边距之内，任何行不得与边框相交。

### 7.3 分页行为

- 每道题在新页开始，上一题不得与下一题共页。
- 短题不为了填满页面而拉大间距。
- 长题从首页剩余空间开始使用，不提前制造空白续页。
- 标签的保留空间不足时，标签和正文起始整体移到下一页。
- 表格行、评分刻度和面试官记录区按组件边界整体移动；无法完整放置时不得截断。

## 8. 生成架构与数据流

实现继续使用现有 ReportLab 管线，并维持以下边界：

1. `parser.py`：把 Markdown 解析为稳定的 `QuestionBank`、`Section`、`Question` 和 Block 模型。
2. `styles.py`：注册嵌入字体并提供不可变视觉令牌和 `ParagraphStyle`。
3. `components.py`：只负责章节页、题目标题、字段面板、表格和记录表等可复用 Flowable。
4. `document.py`：负责文档顺序、PageTemplate、页眉页脚、TOC、bookmark、题目起始分页和最终构建。
5. `verify.py`：独立验证内容完整性、结构、字体、页面和最终哈希。

数据流：

`Markdown -> parse_question_bank/build_sections -> QuestionBank -> build_story -> ReportLab multiBuild -> 临时 PDF -> 结构与视觉验证 -> 原子替换最终 PDF`

两遍构建用于生成目录和总页数。最终文件只能由已完成验证的临时文件原子替换，构建失败时保留上一份有效 PDF。

## 9. 错误处理

- 字体缺失或中文字形覆盖不足：立即失败。
- 题号重复、题目数量不符、题组能力映射缺失：立即失败。
- Markdown 中必需字段缺失：报告准确题号和字段，不生成不完整正式文件。
- TOC 或总页数仍含占位符：验证失败。
- 临时文件生成失败：删除本轮临时文件，保留旧正式文件及其权限。
- 渲染、文本抽取或 outline 验证失败：不得发布正式文件。
- 任何已知裁切、重叠、乱码或黑方块：视为发布阻断，不以“内容可抽取”替代视觉修复。

## 10. 验收标准

### 10.1 内容完整性

- 80 道题全部存在，题号无重复或遗漏。
- 12 个二级章节、全部题组、非题目三级章节、4 张表、评估与记录模板完整。
- 问题、题前材料、项目情景、考察点、答案要点、追问、风险信号、评分锚点和参考入口按源文档完整输出。
- 文本抽取不得出现 `<details>`、`<summary>`、工具令牌或生成占位符。
- 源 Markdown 的 SHA-256 写入构建回执，证明内容快照可追溯。

### 10.2 结构与交互

- 页面尺寸为 A4。
- metadata、目录、outline、bookmark 和内部跳转可用。
- 页眉章节、题号和续页状态与当前页面内容一致。
- 页码和总页数准确，不出现 `?` 或旧版页数。
- 最终文件权限为 `0644`。

### 10.3 几何与分页

- 所有 Flowable 宽度不超过 Body Frame。
- 题目页集成标签行与正文行的相交高度为 0；允许共边，不允许面积重叠。
- 外置标签到面板、面板到下一外置标签的净距均不小于 3 pt。
- 正文与页脚安全区无相交。
- 最长答案能够跨页并包含结尾标记。
- 标签不会单独留在页底。
- 一题一页的起始合同成立，长题续页不丢字、不重复、不裁切。
- 不出现意外近空白页。

### 10.4 视觉检查

- 使用 Poppler 以 144 DPI 渲染全部页面为 PNG。
- 检查全部联系表，并逐页复核所有可疑页面。
- 必查封面、文档控制、目录、岗位路线、首个章节页、首题、带盲面材料的题、最长题、宽表、综合评估、记录表和末页。
- 无裁切、重叠、黑方块、乱码、孤立标题、不可读字号或失真的代码路径。
- 深色页和白底页都需检查彩色与灰度可读性。

### 10.5 回归验证

- 现有 PDF 单元测试和验证器全部通过。
- 为标签/面板双向净距、续页页眉、孤立标签、正文/页脚安全区和章节装饰安全区增加定向回归测试。
- 每次有意义的视觉修改后重新生成、重新渲染并重新验证，不复用旧 PNG 作为新版本证据。

- 不修改 `docs/project-interview-question-bank.md`。
