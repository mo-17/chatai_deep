## 修复与回归

- 生成记录表复用 `SchemaGuard` 查询现有列后补齐，修复鸿蒙重复列错误只提供通用 `14800021`、无法匹配英文错误文本而导致会话未就绪的问题。新库、重复初始化、旧表补列与旧记录保留均通过回归。
- 安全存储改用 ArkTS `util.TextEncoder`、`TextDecoder`、`Base64Helper`，修复 Buffer
  字节视图偏移造成的 `RangeError`；HUKS 别名及 v1 密文的 nonce/tag/AAD 格式不变。
- 播放、OCR、PDF 预览和分享的文件边界兼容应用及 Ability 模块两个上下文的沙箱目录，
  保留路径分隔、遍历、链接、文件大小等现有限制。语音播放仍仅接受语音缓存子目录。
- AVPlayer 的 `audioInterruptMode` 移到 prepared 后设置，修复真机 `5400102` 错误。
  该状态要求见 [OpenHarmony AVPlayer 属性文档](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/reference/apis-media-kit/arkts-apis-media-AVPlayer.md)。
- 耳机首选路由还必须与实时连接清单中的设备 id、方向和类型一致；媒体收音设备从媒体输入列表选择，避免仅凭残留的首选项开放双工。激活通信会话前先验证当前耳机输出通路，尊重系统关闭音频的选择；蓝牙启用时允许 A2DP 预检，激活后仍要求 SCO 收放音。
- PDF Kit 像素图直接传入 Core Vision 时，真机返回 `1001400001`；保持页面尺寸上限，
  使用有界 PNG 重解码为 RGBA 后识别，并完整释放编码器、解码器及像素图。

76 项原生/构建测试与 36 项数据库/生成流程测试全部通过，涉及新增 12 项回归用例；安全存储替身使用真实 Node AES-GCM，
验证中文/emoji、v1 兼容、随机 nonce、AAD/tag 篡改拒绝和失败后恢复。
原生服务在这些主机测试中使用替身；上表真机结果来自实际应用进程与系统服务，分别记证。
Release 构建完成独立 AOT、HAP 原生库和许可证校验。临时阶段诊断代码已移除。
