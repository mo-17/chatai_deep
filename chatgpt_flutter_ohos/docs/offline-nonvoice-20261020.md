## 取消和文件生命周期

取消是协作式的：发出精确请求 ID 的原生取消，等待当前系统 API 返回并释放资源；同步 PDF 解析不能强制中断。Dart 最长等待 2 分钟，超时后原生仍忙时拒绝并发，界面明确提示稍后重试。取消或账号失效后丢弃迟到识别结果，不保存半份 OCR 正文；已经提交的完整文档保留。

进度弹窗只移除本次任务创建的路由，不能误关闭账号切换后打开的新页面。ZIP/目录临时资料直到明细及重试结束才释放，仍只删除本次专属副本，不删除源目录。

新图片存入应用 filesDir/chatai_picked_images，只有尚未交付业务层的 pending_image_* staging 参与缓存过期及配额。恢复时同样先复制、校验并持久保存新路径，再删除 staging；确认消费记录后图片继续可用。持久图片和历史缓存不做盲目自动删除，因它们可能仍被聊天、头像或草稿引用；这不是整个应用磁盘占用的 512 MiB 上限。恢复记录损坏时保守保留 staging；满额会拒绝新选择而保留草稿。拒绝符号链接及非文件，恢复记录的显示名称不能决定输出路径。

## 复现

仓库根目录执行（先准备 pnpm 依赖及普通 Flutter 3.35.7，不使用 Flutter OH 跑宿主测试）：

```sh
pnpm install --frozen-lockfile --ignore-scripts
FLUTTER_BIN=/path/to/flutter-3.35.7/bin/flutter bash chatgpt_flutter_ohos/scripts/test-offline.sh
```

脚本也可使用 PATH 中的 Flutter，并在执行前校验版本。首次解析依赖可能联网；测试不使用真实账号、AI 服务、HDC 或 DevEco。原生测试执行实际插件方法体，系统 API 使用替身。核心使用临时文件、真实 SQLite 事务和实际页面组件。

Release 另行在配置好 mise/DevEco 的主机执行：

```sh
cd chatgpt_flutter_ohos
eval "$(mise activate zsh --shims)"
eval "$(mise env -s zsh)"
./scripts/build-release.sh ../deploy/flutter/production.json
```

工作流位于 `.github/workflows/ohos-offline.yml`，在 main 推送、PR 或手动触发时运行离线脚本。本轮只提交本地 Git，未推送或触发远程 CI；不声称 CI 已在线运行通过。
