# 2026-10-20 语音稳定性与真实账号补测

基线 `287f1774`；ALN-AL00 / OpenHarmony-6.1.1.120 / API 24，蓝牙通话耳机。
本轮使用固定本地文本和真实系统语音、Sherpa、麦克风、AVPlayer；未发送 AI 聊天请求。

## 语音长测与听感边界

| 项目 | 实测结果 |
| --- | --- |
| 系统离线语音与麦克风循环 | 902,095 ms，153 轮，128 次完整播报、25 次预定停止，153 次麦克风启动与结算 |
| Sherpa 模型语音与麦克风循环 | 第 52 轮完成时 531,893 ms，44 次完整播报、8 次预定停止；用户报告卡顿、失真及异常无声后主动中止 |
| 进程与资源采样 | 同一 PID；20 个样本，FD 147–151、线程 55–60，观察 RSS 约 540–958 MiB |

循环每轮重新准备和释放通话路由，每 6 轮主动停播一次，Sherpa 每轮重新合成不同文本，
并非连续无间隔播放。模型合成约 3 秒；预定停播和合成间隔已向用户说明，用户仍确认后半段
有额外听感异常，因此不能把播放完成回调或进程未崩溃视为长时间听感通过。
停止引发的 `playback_error` 是主动中断的结果，不能作为此前异常的根因。

后续复用同一段 7.703 秒 / 22,050 Hz 单声道模型 WAV 做短对照：
普通媒体通路三次、持续通话路由且不启用麦克风三次，用户均确认连续清晰。
WAV 峰值约 0.768、无削波，未检测到超过 150 ms 的连续极低幅值片段。
持续通话路由加麦克风的三次播放收到完成回调，但没有单独收集听感确认。
这些短对照不能排除长测中出现的问题，也没有据此修改生产音频代码。

用户随后明确表示“目前是能正常使用的”，要求不继续深挖语音；按该范围停止诊断，
长时间模型语音听感记为未通过 / 延后处理，不宣称完成 30 分钟稳定性验收。
RSS 来自调试构建和 USB 供电测试，样本不足以证明无泄漏、温升或功耗合格。

## 真实账号与游客隔离

原账号退出后，token/profile 均为空，原对话页面销毁。通过真实登录页游客入口处理函数进入游客模式：
实际游客首页没有显示原账号会话，当前作用域正确；原账号图片恢复测试记录在游客作用域不可见。
测试记录来自真实系统选择器，取消时保留固定文本及 0 张图片，未导入个人照片。

原账号初始数据库为 1 条会话、0 条消息、0 条助手及 0 条收藏；AI 设置有 16 个服务商，
配置的 API key 数为 0。故本轮不能证明非空密钥的跨账号隔离，相关主机回归单独记录。
用户仅有一个正式账号，本轮覆盖正式账号与游客、退出后原账号重登，不覆盖两个正式账号。

首次真实后端重登后，当前分区与退出前保存的分区不同，原会话及测试草稿没有加载。
用户已确认是同一个正式账号、同一种登录方式。旧分区四张业务表数量仍与基线相同。
随后对同一新登录用户名做 Release AOT / 调试模式对照，两者 hashCode 计算结果一致，
且均不同于最初保存值；没有把这次问题归因于运行模式，最初分区值的具体生成环境尚未定位。

修复为读取旧 profile 时记住已有分区引用，后续登录优先复用该引用。索引键由后端 origin 与
用户名的 SHA-256 摘要组成，索引值只含原分区编号；不保存用户名、token、密码，不扫描数据库猜测归属。
游客不更新正式账号索引，损坏索引会拒绝静默切换空白分区；只读后台存储不写入索引。

根据用户对身份一致性的明确确认，保留新登录的真实认证 token，将本机当前 profile 的分区元数据
关联回已保存的原分区。没有复制或合并业务表；实际首页重新显示原来的 1 条会话。
之后再次执行原账号 → 退出 → 游客 → 退出，游客首页仍不显示原会话，原测试草稿在游客作用域仍不可见。

修复后再次通过真实后端登录，账号分区与最初保存值相同，原表数量全部匹配，实际首页显示原来的 1 条会话。
16 个服务商的原设置值匹配；原账号固定恢复草稿重新可见。临时页面中的真实共享输入框弹出恢复确认，
点击“恢复草稿”后固定文本回填、图片为 0 张，原生记录消费。未发送测试聊天，也未迁移游客数据。
恢复确认使用共享输入框的独立测试页，不能外推为生产导航栈或任意常规草稿的完整恢复。

一次尝试附带音频的退出诊断因 `Headset duplex not available` 提前结束，未计为通过；
按用户停止深挖语音的要求，随后只执行正常退出流程并核对 token/profile 与旧页面销毁。

## 登录传输条件

手机直接访问配置的后端域名时连接被重置；电脑可访问。测试临时通过 USB 上的限定目标 TCP CONNECT
通道转发该域名的 TLS 流量，实际 AuthApiClient 的 public-config 返回 code=0 后才退出账号。
通道不解密 TLS，不记录凭据；没有关闭证书校验，也没有改源码或持久化后端配置。
这证明的是临时传输路径上的真实认证，不能据此宣称手机直连后端网络问题已解决。
